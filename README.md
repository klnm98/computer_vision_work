# 木块识别系统（Wooden Block Detection）

用**真实、公开的数据集**训练一个深度学习目标检测模型，在摄像头画面中准确
框选出木块（类似 `block.jpg` 中的木块），并保证**不会框到其他物体**，
木块**缺角时依然能识别**。

> 与原来的 `detect_camera.py`（Otsu 二值化 + 轮廓 + 长宽比）不同：
> 规则法依赖"木块与背景颜色/亮度差异明显"，而 `block.jpg` 里的木块与木桌
> 几乎同色，规则法会失效；本方案改为训练一个单类别检测网络，
> 学习木块的**木纹纹理与几何结构**，因此对同色背景、缺角、倾斜摆放都更稳。

## 1. 快速开始

```bash
# 0) 安装依赖（自动装 PyTorch CUDA 版 + Ultralytics）
python main.py setup

# 1) 下载公开数据集并构建训练集（约 2 GB 图片 + 0.66 GB 标注包）
python main.py prepare

# 2) 训练（RTX 4050 约 40~70 分钟）
python main.py train

# 3) 评估（mAP、误检率、召回率、缺角测试，输出报告到 reports/）
python main.py eval

# 4) 摄像头实时识别
python main.py camera

# 对单张图片识别（如 block.jpg）
python main.py image block.jpg

# 一键完成 1→3
python main.py all
```

不带任何参数运行 `python main.py` 时：**若已有模型就直接开摄像头**，
若还没有模型则自动执行 `prepare → train → eval`。

也可以直接使用 `detect_camera.py`（主进程仍推荐 `main.py`）：

```bash
python detect_camera.py                     # 默认摄像头
python detect_camera.py --source 1          # 第 2 个摄像头
python detect_camera.py --source block.jpg  # 单张图片
python detect_camera.py --source demo.mp4   # 视频文件
python detect_camera.py --conf 0.45 --no-show --max-frames 200
```

摄像头窗口中：`q` 退出，`s` 保存当前带框截图。

## 2. 数据集：真实、公开

| 数据集 | 用途 | 说明 |
| --- | --- | --- |
| **YCB-Video Dataset**（YCB Benchmark, Yale GRAB Lab / NVIDIA） | 训练 + 验证 | 真实拍摄的 92 个桌面场景、133,936 帧，21 类日常物体，每帧带 2D 框标注。本项目只用其中的 **036_wood_block（真实木块）**，共 **15 个场景**含木块。 |
| **BOP YCB-V**（BOP Challenge 官方整理版，MIT License） | 独立测试（误检率 / 召回率） | 官方测试集 1000 张真实图像，含 `scene_gt` 与 `scene_gt_info`（物体 2D 框、可见比例）以及实例掩码。 |

* **不使用**自采数据、**不使用**合成/仿真数据、**不使用**网络爬取的未标注图片。
* 训练场景（0000-0091 中除 0048-0059 外）与测试场景（BOP 测试集 0048-0059）
  **完全不重叠**，验证集也按**场景**切分，避免同一段视频的近重复帧造成指标虚高。
* 标注格式：`*-box.txt` 每行为 `<物体名称> <x1> <y1> <x2> <y2>`。
* 下载方式：通过 HTTP Range **只取需要的字节**（场景压缩包 1~3 GB，标注文件仅
  ~160 字节），单个场景按需拉取，避免下载数十 GB 全量数据。

## 3. 方法

```
摄像头帧 ──> YOLO11s 单类别检测器(wood_block) ──> 形态过滤 ──> N-of-M 时序确认 ──> 画框
```

* **单类别模型**：网络只输出 `wood_block` 一类，结构上不可能把桌子、手、
  其他物体"当成"某一类物体框出来。
* **迁移学习**：从 COCO 预训练的 YOLO11s 微调，小数据集也能收敛。
* **强数据增强**：HSV（色相/饱和度/亮度）、旋转 ±20°、缩放 0.6、透视、
  Mosaic、MixUp —— 用于跨越"数据集里的固定相机 / 桌面场景"与
  "手机摄像头实拍"之间的域差异。
* **三种针对性离线增强**（都基于真实公开图片生成，标签同步更新）：

  | 增强 | 比例 | 目的 |
  | --- | --- | --- |
  | 缺角增强 | 25% | 把木块一个角"敲掉"，用相邻背景填补 —— 满足"缺角仍能识别" |
  | 遮挡增强 | 20% | 用其他位置的纹理挡住木块 20%~45% —— 对应被瓶子/手挡住的真实情况 |
  | 近景放大 | 35% | 围绕木块裁小窗口再放大 —— 补上"木块占满画面"的大目标样本 |

* **负样本**：把 40 个"不含木块但同样杂乱"的真实场景（每场景 20 帧）以空标签
  加入训练，显式压制误检。

### 为什么"不会框到其他物体"

| 手段 | 作用 |
| --- | --- |
| 单类别检测 | 网络无其他类别输出 |
| 置信度阈值 | 在真实负样本上标定（见 `reports/evaluation.md`） |
| 形态过滤 | 丢弃极端狭长 / 过小的框 |
| N-of-M 时序确认 | 连续多帧命中同一位置才画框，抑制单帧偶发误检（摄像头模式默认开启） |

### 5.2 已知限制与取舍（实测）

**① 木块占满画面时的近景**：YOLO 的输入会被统一归一化到 640，因此物体在输入里的
相对大小是固定的。训练集（YCB-Video）里木块一般只占画面高度的一小部分，所以
当木块被举到镜头前、几乎占满画面时，单尺度推理可能漏检。打开"多尺度重采样"
（`--scales 1.0,0.7,0.45`，预先缩放会引入不同强度的重采样/模糊）可以补上这种情况，
代价是误检率上升。实测：

| 推理尺度 | BOP 负样本误检率 | 木块召回率 | `block.jpg` 原图 | 近景（木块占满画面） |
| --- | --- | --- | --- | --- |
| `1.0`（默认） | **0.85%** | 73.3% | ✅ 0.83 | ❌ |
| `1.0,0.75` | 3.03% | 74.7% | ✅ 0.83 | ❌ |
| `1.0,0.7` | 3.88% | 73.3% | ✅ 0.83 | ❌ |
| `1.0,0.7,0.45` | 8.73% | 73.3% | ✅ 0.84 | ✅ 0.46 |

因为"不框到其他物体"是硬要求，默认采用单尺度；确实需要拍近景时再加 `--scales`。

**② 极端遮挡/掠射角**：BOP 官方测试集场景 000055 里木块被白色瓶子挡住、且以接近
掠射的角度出现，这类样本召回偏低（整体 73.3% 的漏检主要来自这里）。已通过"遮挡
增强"改善（该版本把召回从 18.7% 提升到 73.3%）。

**③ 框的松紧**：在数据集同分布图像上，命中框与真值的平均 IoU 为 0.74；在
`block.jpg` 这种"木块与木桌同色"的手机截图上，框会明显偏松（把周围桌面也包含
进来），但不会框到**其他物体**（BOP 1000 张真实图里只有 5 个框落到其他物体上）。

**④ 训练过程记录**：本项目一共训练了 3 个版本，最终上线的是在官方测试集上召回
最好的 v2：

| 版本 | 做法 | 验证集 mAP@50 | BOP 木块召回 | BOP 误检率 |
| --- | --- | --- | --- | --- |
| v1 | 12 个场景、步长 8、只有缺角增强、早停于第 26 轮 | 0.797 | 18.7% | 19.15% |
| **v2（默认上线）** | 15 个场景、步长 12、缺角 + 遮挡增强、40 个负样本场景 | **0.828** | **73.3%** | **0.85%** |
| v3（附带模型 `models/wood_block_v3_zoom.pt`） | v2 数据再加"近景放大"增强 | 0.867 | 20.0% | 1.21% |

v3 在验证集上更高、也能认出"木块占满画面"的近景，但在更难的 BOP 官方测试集上
召回反而更低，所以默认仍用 v2；需要拍很近的特写时可临时 `--weights models/wood_block_v3_zoom.pt`。

## 6. 常见问题

**Q: 摄像头能正常用，但弹出来的窗口是纯黑的怎么办？**

**现在不需要你手动排查了**——`detect_camera.py` 启动时会自动做这件事：

1. 先试上次成功的组合（结果记住在 `.camera_config.json`，第二次启动秒开）；
2. 失效则**自动完整自检**：枚举 `设备号 0~5 × 后端(dshow/msmf/any) × 分辨率(1080p/720p/480p/不设置)`；
3. 判定标准是"能连续读出**非黑屏**画面"（亮度 + 标准差），**黑帧不算可用**；
4. 按 **分辨率高低 + 有效帧比例 + 画面稳定性** 打分选最优，并打印选择的理由；
5. 运行中若掉线或持续黑屏（约 3 秒），**自动重新排查并接管**，无需重启程序。

启动日志会直接告诉你结果，例如：

```
[摄像头自检] 找到以下可用组合（按推荐度排序）：
   设备 0 / msmf  / 1280x720   有效帧 10/10  亮度 141.3  抖动  0.3  评分 3.03
   设备 0 / dshow / 640x480    有效帧 10/10  亮度 100.4  抖动  4.2  评分 1.42
[摄像头自检] 以下组合能打开但画面全黑/纯色（通常是虚拟摄像头）：
   设备 0 / dshow / 1280x720：能打开但全黑（亮度 0.0）
[摄像头] 自动选择：设备 0 / 后端 msmf / 1280x720（评分 3.18）
```

想只看自检结果（不启动识别）或强制重新排查：

```bash
python detect_camera.py --probe     # 或 python main.py camera --probe
python detect_camera.py --rescan    # 忽略记忆，重新自检
```

常见原因（都已自动规避或给出提示）：

| 现象 | 原因 | 现在的行为 |
| --- | --- | --- |
| 某个后端 + 某分辨率全黑 | 驱动在该分辨率下不出图（实测 DShow+1280×720 就会全黑） | 该组合被判为"能打开但全黑"并跳过，自动换分辨率或后端 |
| 0 号设备全黑 | 0 号是虚拟摄像头（OBS/虚拟相机等） | 自动改用其它设备号并提示 |
| 前 1~2 秒黑屏 | 摄像头预热/自动曝光未就绪 | 默认丢弃前 20 帧（`--warmup 30` 可加大） |
| 运行中突然黑屏/掉线 | 摄像头被其它程序抢占或休眠 | 自动重新选择设备并接管（最多 3 次；`--no-recover` 可关） |
| 完全找不到可用组合 | 被相机/会议软件独占，或 Windows 隐私设置禁止桌面应用访问摄像头 | 报错并列出逐条排查步骤 |

需要人工指定时仍可用 `--source N --backend msmf`，此时程序只在指定后端里试，并会自动换设备号。

**Q: 换一个木块（颜色/大小不同）还认得出来吗？**
模型学的是"木块"这一类的外观（木纹、方形块状结构），并通过强颜色增强降低
对具体色调的依赖，因此对浅色/深色木块都有一定泛化能力。若换成差别很大的
目标（如塑料积木），建议用自己的数据再微调。

**Q: 摄像头检测会不会闪？**
摄像头模式默认开启 N-of-M 时序确认（连续 3 帧命中才画框），并对框做了指数
平滑，因此画面稳定。可用 `--no-temporal` 关闭。

**Q: 没有 GPU 能跑吗？**
能。`--device cpu` 可以纯 CPU 推理（速度慢一些），但训练强烈建议用 GPU。

**Q: 训练/推理时会不会联网？**
`prepare` 阶段需要联网下载公开数据集与预训练权重；训练与推理完全离线。
`models/pretrained/` 里已放好 `yolo11s.pt`（COCO 预训练），若该文件存在就不会
再去下载。

## 7. 受限运行环境说明（可选阅读）

本仓库在只能写工作区、且禁止命名管道通信的沙箱环境里也能跑通，为此做了三处
**兼容处理**（在普通环境下这些处理是无害的，可以忽略）：

| 问题 | 处理方式 | 位置 |
| --- | --- | --- |
| pip 无法往 `tempfile.mkdtemp` 创建的 0700 目录写文件 | 把 pip 临时目录设到工作区，并让 `os.mkdir` 以可写权限创建临时目录 | `woodblock/env_setup.py` |
| Ultralytics 要把配置写到 `%APPDATA%\Ultralytics`（不可写） | 通过 `YOLO_CONFIG_DIR` 重定向到项目根目录 | `woodblock/__init__.py` |
| Ultralytics 标注扫描用 `multiprocessing` 线程池（依赖命名管道，被拒绝）；DataLoader 多进程 worker 同理 | 换成等价的顺序实现，并把 `workers` 设为 0 | `woodblock/compat.py` |

如果希望恢复多进程数据加载（普通环境、追求训练速度），设置环境变量：

```bash
set WOODBLOCK_ALLOW_WORKERS=1
```
